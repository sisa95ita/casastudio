# Furniture authoring in the 2D editor

Furniture is a top-level tool between Stair and Measure. Its catalog lives in Inspector Properties and reads `builtinFurnitureDefinitions` from the schema package. The catalog shows the canonical semantic category and display name. There is no additional product catalog or canvas form. Furniture has no keyboard shortcut: F is already assigned to fit the viewport, and the remaining letters do not offer a clear unused mnemonic.

Choose a definition, move the pointer into a Room, and click to place. The definition supplies initial width, depth, and height; rotation starts at zero. The instance follows the pointer in canonical Project X/Z centimeters with bounded smart snapping and the independently controlled grid snap. After confirmation the tool retains the definition and effective parameters for another placement. Escape or Cancel removes the proposal; changing tool or Level, undo/redo, and session boundaries clear transient state without implicitly creating anything.

Room targeting uses the center point, including polygon boundaries. Ordered Wall-backed, free, and mixed Room boundaries all participate. Only Rooms on the active plan are placement candidates, including Rooms elevated above that Level. No direct Level choice is exposed for Furniture. Final placement uses the actual oriented footprint: Wall-body overlap and same-floor Furniture overlap are invalid, Wall tangency is valid, and Stair overlap is warning-only.

A single candidate resolves automatically. No candidate means an invalid visible preview and no commit. Overlapping candidates require an explicit Room choice in Properties, with Room names and unit-aware global floor elevations. A placement's explicit choice remains valid while that Room contains the center, and is cleared when the pointer leaves it. Moving an existing item preserves its current Room whenever it remains a candidate; a single different candidate reassigns automatically. An ambiguous numeric move or completed drag remains a proposal until the user chooses a Room and confirms in Properties. An outside-Room move is rejected and the canonical instance remains unchanged.

Selecting an instance shows its catalog display identity/category, Room, exact X/Z, width/depth/height, and rotation. Definition ID and Room floor elevation are read-only. Unknown definitions use a generic symbol and remain selectable, editable, duplicable, and deletable. Numeric fields require finite values; dimensions must be positive. Room reassignment is restricted to Rooms containing the current center. Exact rotation remains available through Properties as the keyboard-accessible alternative to the SVG rotation handle.

Dragging preserves the initial pointer-to-center offset and uses the viewer's five-CSS-pixel gesture threshold. Rotation uses the canonical positive-Y right-hand convention around the centered anchor and supports arbitrary angles. Gestures update transient state only, then dispatch one full Project snapshot on completion. Space+drag retains viewport panning. Escape and pointer cancellation abandon the gesture. Duplicate starts a detached placement carrying effective dimensions, rotation, and metadata; it creates a new stable UUID identity only on confirmation. Delete removes only the selected instance and also supports the established Delete/Backspace shortcut.

Smart snapping is on by default while placing or moving Furniture. Its activation distance is measured in CSS pixels, so zoom does not change how close the pointer must be. Architectural targets take precedence over decorative alignment: a compatible oriented Furniture edge can become tangent to a physical Wall face, while nearby Furniture edges and plan-space centers can align with restrained transient guides. Candidate placements are validated before they may affect the preview, and Furniture on different Room-derived floor elevations is excluded from ordinary object alignment. Holding Alt/Option during the active gesture temporarily bypasses smart and grid snapping without bypassing Room or collision validation.

Multi-selected Furniture moves as one rigid aggregate and receives one snapped delta; members are never snapped independently. Properties exposes footprint-based left, horizontal-center, right, top, vertical-center, and bottom alignment. The last-selected item is the stationary alignment anchor. With three or more items, horizontal and vertical distribution keep the geometrically outer items fixed and create equal clear gaps between actual footprint extents. Alignment and distribution first build and validate the complete candidate Project, then commit one history snapshot or reject the operation without changing the selection.

`FurnitureItem` feeds a renderer-neutral `FurniturePresentationModel2D`, then `FurnitureSvgLayer`. The presentation owns immutable canonical coordinates, centered footprint, arbitrary rotation, symbol polylines, semantic identity, and rotation-handle anchor. SVG projects those points through the shared viewport transform. BED, SOFA, TABLE, CHAIR, CABINET, and DESK have restrained vector cues; GENERIC and unresolved definitions use a neutral footprint. Hit targets cover the whole footprint with an additional practical stroke. Hover and selection alter styling only, preserving legibility.

The Furniture layer defaults to visible. Hiding it removes committed symbols and hit targets and clears Furniture selection. Transient authoring previews remain visible independently, consistent with other authoring overlays. Furniture does not add controls to the status bar. Desktop/tablet use the existing Inspector surfaces; phone editing remains disabled.

Furniture owned by lower and elevated Rooms may occupy identical X/Z coordinates. Persisted order is the deterministic paint order, while repeated overlapping hits cycle deterministically. Elevation is always derived from the owning Room and its Level, and changes when Room ownership or Room elevation changes.

All commits use canonical schema operations and existing full-Project persistence/history. Room deletion/dissolution consumes the canonical resulting Project, including its Furniture deletion/transfer; the editor removes selection references to deleted instances. Precision candidates and guides remain presentation-only and never enter Project data or history. No Geometry Snapshot fields, REST resources, schema changes, schema version bump, database migrations, 3D assets/rendering, resize handles, or AI fields are involved.
