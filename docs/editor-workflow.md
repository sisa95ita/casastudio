# Project editing workflow

A new Project opens in View with an empty Ground Floor at elevation zero. Edit plan creates an independent draft of the authoritative Project. Levels, Walls, Rooms, Openings, Stairs, and Room-owned Furniture are saved together; switching Levels keeps the same draft and cancels selection and unfinished authoring. Active Opening and Stair tools restore usable default Properties after cancellation without restoring a positioned preview. Project changes reset Room authoring defaults and obsolete feedback; Furniture drops old canvas anchors and feedback across Level and tool changes.

Room shapes and Wall-first detection both produce ordered canonical Room boundaries. Elevated Rooms have local elevation above their Level and may use free floor extents without creating physical Walls. Stairs reference source/destination Levels and optional Rooms. Furniture derives its Level and floor elevation from its owning Room.

Room Shape placement treats every final Rectangle, L, U, or T footprint vertex as a precision source, including after rotation. One selected correction translates the complete footprint rigidly, preserving dimensions, rotation, and elevation. Current-Level targets come from the active draft Level's canonical Wall endpoints; equal coordinates retain every incident Wall ID and outrank generic runtime vertices and lower-Level reference endpoints. After translation, every coincident preview vertex is presented, while complete edge alignment is reported only for an exact canonical Wall or contiguous Wall chain. Domain-owned Room creation independently plans the topology: it normalizes only sub-tolerance floating-point drift onto same-Level Wall axes, reuses exact Walls and ordered chains, splits existing Walls at every required Room-edge endpoint—including two points on one containing Wall—and creates canonical fragments only for uncovered edge ranges. Covered fragments become shared while residual fragments retain their existing Room ownership and Opening placement. A perpendicular Wall endpoint may terminate at a canonical junction between reused chain segments without being misclassified as a crossing. Precision metadata does not create topology. Ambiguous overlaps, proper crossings, Opening-cutting splits, and non-manifold ownership remain invalid.

An enabled lower-Level reference supplies presentation and positional precision only. It appears as a transient Layers row, defaults to visible when a lower Level exists, and exposes subtle endpoint markers only during Room or Wall authoring. Reference targets cannot be selected or edited. One rigid correction may align and present both endpoints of a compatible reference edge, but snapping copies only Project X/Z coordinates: the active Level creates its own Walls and never stores cross-Level topology, shared vertices, or snap metadata. Toggling the reference changes neither the Project draft nor history.

Save replaces the whole Project using its editing base revision, refreshes both Project and Geometry responses, and returns to View. The active Level is retained through Save, Back to project, and the 3D → Edit in 2D transition when that Level still exists. Reloading the browser starts a fresh View on the default Level.

Dirty state compares the current draft with the authoritative editing base. Returning to that exact base is clean, even if Undo history still exists. History retains at most 50 actions; exhausting that bounded history does not imply that the draft matches the saved Project. Undo/Redo clears transient interactions and selection and always targets a Level present in the resulting draft.

Discard removes the editing session and its history and returns to authoritative data. Dirty navigation offers Save, Discard changes, or Keep editing; browser unload is also guarded. Switching Levels stays within the session. The 3D representation is available in both View and an active edit session. View remains read-only; Edit renders the same unsaved draft used by 2D.

A stale save receives a revision conflict and retains the local draft. It cannot overwrite newer server data. Reload latest requires confirmation before discarding local work. A successful save whose authoritative refresh fails is retried as a read, without repeating the write.

Layers affect presentation and selection only. Hidden Walls, Rooms, Openings, and Furniture are excluded from selection and overlap cycling; collision validation continues to use canonical data. Layer preferences reset on Project changes. Selection, hover, previews, guides, catalog category filters, label placement, and snap candidates are never persisted in the Project.

Level authoring stays in the Level workflow. Create from level below is present only for an active empty upper Level with a lower Wall footprint; it copies Walls with new IDs as one validated history action and does not copy Rooms, Furniture, Openings, or Stairs. Level deletion is available only for the deterministic highest Level, using elevation and durable Level order as the tie-breaker, and a Project must retain at least one Level. Deletion atomically removes the Level-owned Walls, Openings, Rooms, and Stairs; Room-owned Furniture; every Stair connected to the deleted Level; and Project artifacts whose references depend on a deleted Level observation. The new highest remaining Level becomes active. Undo and Redo restore or remove the complete dependency graph as one action, and persistence continues through whole-Project Save.

Current 3D supports Walls, Room Floors (including elevated Rooms), Openings, Stairs, Furniture, Level visibility, semantic selection, and fit/reset camera controls. Product-facing copy calls this the 3D workspace: View mode is read-only, while Edit mode allows one selected Furniture item to move or rotate and keeps architectural geometry read-only. Arrow keys reuse the 2D Project-space nudge contract (1 cm, or 10 cm with Shift), including canonical validation and one history action per accepted key press. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, and Ctrl/Cmd+Y use the shared editor Undo/Redo history outside editable controls. Pointer manipulation retains its Room-floor transient preview and commits one canonical history action.
